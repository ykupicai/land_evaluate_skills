# 地籍出圖端到端工作流（清冊 → 成果圖）

把三支子 skill 依序串成一條產線。**本 skill 只做統籌與交接**,每一段的細節在各子 skill。
遇到該段就呼叫該子 skill,不要在這裡重造流程。

## ⚠️ 執行紀律(所有模型適用;Opus/Sonnet 接手時尤其不可違反)

1. **硬閘門必過**:每段交接跑 `scripts/pipeline_check.py` 對應子命令(下方各段標註),
   **exit≠0 就照訊息處置;處置不了→停下回報使用者,禁止繞過或憑感覺續跑**。
2. **瀏覽器操作用現成 driver,不要重寫**:批次選取=tcdgis `scripts/batch_driver.js`、
   收尾下載=`scripts/finalize_download.js`(注入→輪詢狀態即可)。driver 內的節流/重試/
   取消規則是實測傷痕,**嚴禁「優化」**(例:縮短 10.5s 節流、對「查無地號」重試、
   多按一次「確定」)。
3. **遇到 skill 未記載的平台行為**(新彈窗、新元件、新錯誤訊息)→ 截圖+記錄現象,
   **停下回報,不要即興修復**。新版式清冊/平台改版的首跑交給高階模型。
4. **數字只能來自實算**:任何要交付的數量/面積,必須能指出來源腳本輸出;對不上=停。
4b. **★「回報成功」不等於「圖有內容」——每張要交付的圖都要開起來看過**
   （2026-08-04 龍崎案：主題3 出成只有紅框與地號的空白圖，05 清單四張全寫「成功」，
   直到做簡報要引用占比才發現 gpkg 的功能分區圖層是 0 筆）。三個具體檢查：
   - **出圖後的警告一句都不要略過**，尤其是含空白欄位的警告（如「(空白)無地籍圖資」
     ——縣市名是空白就代表欄位取不到值，不是「該案沒有周邊地籍」）。
   - 「圖照出、卻整片空白／主題色沒上」的**既知成因有兩類**：桌面 QGIS 鎖住
     gpkg/tif（見 CLAUDE.md），以及**基地 shp 欄名與讀取端不相容**
     （② area_join 用 `20251201_*`、⓪a cadastre_fetch 用中文短欄名）。
   - 交付前把 pptx 轉 PDF **逐頁目視**（總表列高自動增高，超出投影片的列
     **不報錯也不截斷，而是整列消失**）。
5. 唯二允許自行重試:WMTS 逾時(make_maps 內建)、平台限流訊息(driver 內建一次)。
6. **農業用地變更案一律補做 Ⓒ 隔離綠帶或設施工項**(2026-08-02 使用者定案)——基地是
   農業用地(要點§2② 六類)且要變更作其他使用者,不論走容許使用／變更編定／開發許可／
   都計變更,**都要跑 Ⓒ 並在簡報出「綠帶劃設」與「面積計算式」兩頁**;不要等使用者問。
   ⚠ **例外(2026-08-06 新化王公廟小段1085-1加工廠案確立)**:農業用地變更審查要點
   §2(4)僅管「**非農業使用性質**」之容許使用——若容許使用申請項目本身就是申請農業
   用地作農業設施容許使用審查辦法(M0020022)§3列名七類農業設施之一(農作產銷／林業／
   自然保育／水產養殖／畜牧／休閒農業／綠能),性質仍屬農業使用,**不落入本要點適用
   範圍,不須留設隔離綠帶**,Ⓒ 這步不必跑。判斷法:先看申請的容許使用項目是否為
   M0020022 附表一列名之農業設施細目(如農糧產品加工室);是→跳過Ⓒ;否(如非農業性質
   之設施容許使用)→仍照上述通則跑Ⓒ。

## ★ 都市計畫個案變更（另一條路徑，2026-08-06 安南公塭段醫療専用區案首次走通）

上面整條圖是**非都市土地**案的流程。若⓪a 查回的基地 `使分`/`使類` 為 None（都市
土地訊號），且標的是「都市計畫農業區/保護區變更為XX區」這類個案變更，法規骨架
完全不同，改走這條簡化路徑：

```
⓪a cadastre_fetch（同上，回None即確認是都市土地）
⓪a' cadastre_neighbors（同上，用途是量鄰近分區距離佐證面積門檻例外，非找法定禁止事由）
⓪b ngis_sensitive（同上，都市計畫個案變更**同樣要跑**——見下方更正說明）
Ⓐ' 建専屬用途YAML（config/檢核清單/<用途>_都市計畫_<縣市>.yaml）
   法源＝該分區變更之専屬審議規範/處理原則（如都市計畫農業區變更使用審議規範
   FL003637）為母法＋用途専則（如醫療専用區回饋處理原則FL003631）優先適用専則
   未規定事項；清單項目多半只能寫成note型（門檻/比例/程序條文），非套疊/属性型

   從其規定」不是只指全國性法規（如FL003631），個別都市計畫常另有配合通盤檢討/

③ make_maps --layout maxmap（同上；使用分區/使用地編定會自動疊都市計畫Color1；

   `都市計畫/.版本.txt`。**不要再花時間找線上 API**，詳 CLAUDE.md 同節。
④ parcel-briefing-deck（無Ⓒ隔離綠帶頁；頁面結構走「都市計畫個案變更變體」，

```

**不需要**：Ⓒ隔離綠帶（該規範自己的隔離綠地/退縮規定不是本產線Ⓒ工具管的範圍）、
①TCDGIS平台登入（都市計畫案筆數通常少，⓪a免登入即可取得全部所需幾何屬性，除非
要正式送審才需要平台官方shp背書或環敏53項平台正式套疊）。
⚠ **2026-08-06 更正**：先前這裡誤寫「⓪b環敏NGIS套疊除非案情需要都市計畫案可不跑」，
理由是「審議規範自己有水源保護區等門檻」——**此判斷有誤，使用者當場指出並已更正**：
該類規範條文明列的門檻（如FL003637§15/§16/§18/§19的重要水庫集水區/自來水水質水量
保護區/海岸山地軍事管制區）只涵蓋NGIS 54圖層中的一小部分（地質敏感區、山坡地、
洪水平原、飲用水水源保護區精確範圍等皆不在列），兩者不能互相替代。**⓪b環敏NGIS
套疊對所有案型（含都市計畫個案變更）都是必跑步驟**，不因案型是都市土地而省略。

**面積門檻查核是這類案子最先要做的事**（比照非都市案的Ⓐ第0步禁止事由檢核）：
審議規範通常訂最小面積門檻（如3公頃/5公頃），基地不足門檻時**先查該規範本身
有無特定用途/情境排除條款**（如"目的事業主管機關同意興辦醫療/教育/社福等"或
"已發展地區包圍"），不要機械讀門檻就判死——這類排除條款多半才是案子能否成立
的關鍵，而非後面的規劃細節。查基地周邊分區距離時，可用該縣市都市計畫圖台的
ArcGIS REST identify API 逐筆查證（臺南市範例：`up.tainan.gov.tw`，經
`/AuthToken/proxy.ashx?<真實REST網址>`代理，`TNAreaCheck/TNAreaCheck`圖層可
依座標identify取得逐筆地號的CITYFUN現行分區/PLANNO計畫案號/ORIGIN_DATE編定
日期，比人工地圖判讀精確；Browser screenshot逾時失敗時這是可靠備援）。

## 需要人工/環境的兩個點（先講清楚,不要假裝全自動）

- **①的登入**:`ngis.nlma.gov.tw` 帳密＋圖形驗證碼**由使用者本人輸入**(安全規則:agent
  不可代填、不可解驗證碼)。開好登入頁請使用者完成,回覆「好了」再續。
- **③的環境**:出圖須用 **QGIS 內建 python**(`python-qgis-ltr.bat`);正射套疊/國土利用
  需連 NLSC WMTS(未快取時)、臨路判定需 ②c 臨路評估產物。缺資料的主題單張標失敗續跑。

其餘全自動。

## 逐段交接

### ⓪a 免登入先跑一輪 → 用 `cadastre-check`(★2026-08-02 納入產線)

**先跑這步，再決定要不要／何時佔用平台登入。** 走農業部地籍圖資＋內政部 getLandInfo，
**免帳號、免驗證碼、無 10.5 秒節流**。

```powershell
# 基地
python -X utf8 scripts\cadastre_fetch.py fetch --county <縣市> --town <鄉鎮> `
    --section <段名含小段> --landnos <地號...> --out <案>\cadastre --name 基地
# 鄰地（★2026-08-06 起改自動發現，不必手動列地號清單）
python -X utf8 scripts\cadastre_neighbors.py --joined <案>\cadastre\基地.shp `
    --out <案>\cadastre --buffer 50
```

**鄰地自動發現的原理（`cadastre_neighbors.py`）**：先用本機縣市地籍快照做**空間識別**
（外擴50m內有哪些地號，只認身分不採其屬性），再把發現到的地號逐一餵回 ⓪a 即時查，
拿到現行使分/使類/登記面積/權屬——跟基地本身同一組免登入權威來源，口徑一致。
產出 `<案>\cadastre\鄰地.shp`，取代舊快照或 WMTS 疊圖作為使用分區／使用地編定等
主題圖與評估判斷的基準（`make_maps.py` 的 `ZONING_WMTS` 已改預設 `False`，WMTS
降為 `--zoning-wmts` 備選）。

⚠ **本機快照可能漏收「已從舊地號分割出的新地號」**（尤其交通用地/公路用地——地籍
重測系統只涵蓋「地籍圖重測」，不涵蓋「逕為分割」，兩案已實踩：七股66-23分割出
66-33~47共15個新地號、67分割出67-1/5/9/10/11；後壁103分割出103-1/103-2、113分割
出113-2）。已內建**覆蓋率自我檢查**（本機快照候選聯集 vs 即時回填後聯集，緊鄰20m
內比對）＋**自動探測補正**（抓到落差就找候選宗地母號、批次探測子號1~80、只留真正
落在缺口範圍內者，全程免人工介入，兩案實測最終「缺口已補齊、覆蓋率檢查通過」）。
探測候選母號務必用**整塊缺口幾何**（不是單一取樣點——修復前的缺口常橫跨多個母號，
單點取樣只會找到其中一側，另一側完全不會被問到）。

| **都市計畫** | **只查基地** | 都市土地鄰地分區走本機 `都市計畫/` shp，不靠 nluz |

判準＝基地 `使分` 欄有值的比例（`detect_land_kind()`），`--neighbors on/off` 手動覆寫；
鄰地範圍取 `make_maps.compute_scale_extent()` 算出的實際出圖框（＋`NEIGH_EXPAND`）。

四支腳本一條龍（全部系統 Python，**不需 QGIS**，除最後出圖）：

```powershell
# ⓵ 基地涉及公路時才跑：部分變更編定（道路分割出去維持農牧，綠帶分母＝分割後申請範圍）

# ⓶ 綠帶本體（送審計算式用 --shape minimal；--facility-near 分類臨路側為隔離設施）
python -X utf8 scripts\greenbelt_ratio.py --joined <申請範圍.shp 或 面積join.shp> `
    --neighbours <鄰地_含保留地.shp> --facility-near <保留_道路.shp> `
    --only-on 農業用地 --shape minimal --min-width 1.5 --ratio 0.30 --out <案>

# ⓷ 送審計算式圖說（三角形分割、底×高÷2、比例檢核；內建正確性閘門）
python -X utf8 scripts\greenbelt_triangles.py --joined <申請範圍.shp> --retained <保留_道路.shp> --out <案>

# ⓸ 綠帶配置圖（＝③d 補充主題圖之一；正射底，隔離設施／隔離綠帶分色並列圖例）

```

⚠ ⓸ 是**出圖步驟**，需 QGIS 內建 python；跑在 ③ 那一段也可以（它就是 ③d 補充主題圖的
`--theme 隔離綠帶`）。⓵~⓷ 是系統 python、不需 QGIS，可在出圖前先跑完。

**六個非直覺處（都是實踩，違反會出錯或被審查打回）**：

1. **`--only-on 農業用地` 是必要的**：義務只對相鄰農業用地，**臨道路／未登錄地側不必留**。
   畫成全周界＝把義務算大，會多留綠帶、多拆建物。
2. **分母是「申請範圍」不是原地號**：部分變更編定時分割出去的道路不計入
   （前例反算驗證：1,585.396 ÷ 4,897.97 ＝ 32.37%）。
3. **`--shape minimal` 要配 `--ratio-max`**（預設 ratio+0.03）：無上限時「頂點最少」
   會把基地退縮到形狀最單純為止（實測退到綠帶 76.79%，讓掉大半土地）。
4. **銳角從基地端解決，不要修剪綠帶**：綠帶＝基地−可配置範圍，基地有銳角綠帶必然跟著有。
   事後修剪會破壞寬度合規（實測真不足 0→10/11 點）。用 `split_road` 的 `trim_spikes`
   在切分階段剔除，或靠 `greenbelt_ratio` 的 `chop_needles` 從可配置範圍截平。
5. **臨路側＝隔離設施、其餘＝隔離綠帶**（要點§11 隔離設施得為通路／空地等非建築開放性設施，
   兩者均計入面積比）。分界必須是**直線端點對接**、各為完整一段——不可用 buffer 交集
   （會有圓弧邊界與並排細長條）。
6. **`--neighbours` 要用平台官方鄰地層**：本機地籍是舊快照，近年變更編定的鄰地會判錯側

### ③b 存 QGZ 供修編(★產簡報前必做,使用者定案)
出圖時**不要帶 `--no-qgz`**(預設就會寫),完成後即產 `<案名>_maxmap.qgz`——內含全部
圖層(gpkg 複本/底圖 tif)與**每主題一個 Layout**,使用者可在 QGIS 開啟手動修編再匯出。
若先前為求快帶過 `--no-qgz`,產簡報前補跑一次
`make_maps <案名> --trust-shp ... --skip-extract --layout maxmap`(重用 gpkg 與底圖快取,
只重算圖與寫 qgz)。**確認 qgz 存在且可開(層/Layout 齊)才進 ④**。

### ④ 簡報產製 → 用 `parcel-briefing-deck`
出圖完成後,以 ①的屬性 Excel＋③的 圖層.gpkg/圖檔_maxmap(＋②c 臨路成果,若有)產
評估案簡報:先 `case_stats.py` 實算統計(數字只能來自這份 JSON,範本敘述句要覆核,
不可照抄),再依 **v1 定案格式(9 頁)** 組 pptx 並跑 validate＋逐頁目視 QA。
