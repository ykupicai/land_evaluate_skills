# 地籍評估案簡報產製

**版面狀態:已定案(v1,2026-07-15)。** 格式基準=使用者修正後的官田 v1:
`大量圖資轉換工具/outputs/20260707官田maxmap/20260707官田綠能設施興建評估_簡報_v1.pptx`
(9頁)。新案以 v1 為結構藍本,不要回退 7 頁初版。

## 前置:先有 QGZ 再做簡報(使用者定案)

產簡報前確認 `<案名>_maxmap.qgz` 已存在(make_maps 預設會寫;帶過 `--no-qgz` 就補跑
`--skip-extract` 產出)——使用者要能在 QGIS 開專案修編圖面。qgz 含全部圖層與每主題
Layout;若使用者修編後重匯出了某張圖,簡報改用修編後的版本。

## 原則:數字全部實算,不抄範本句

先跑 `scripts/case_stats.py` 把統計算出來,簡報**只能寫這份 JSON 有的數字**:

```powershell
python scripts/case_stats.py --xls <屬性.xls> --gpkg <圖層.gpkg> --sites <sites_status.csv> -o stats.json
```

範本的敘述句要覆核,不可照抄——官田案範本寫「土地權屬皆為私有地」,實算是
**144 私有＋1 公有**(番子渡頭段157,國產署),照抄就寫錯。同理「鄰近道路系統」不可憑
印象寫:裁切正射套疊 PNG 讀 NLSC 路名標示(官田案讀到 國道3號/官田系統交流道),
並用 sites_status 的臨路狀態佐證。

## ★★ 章節順序（既定，不得擅改）

**壹 基地區位 → 貳 基地現況 → 參 土地使用分區及編定 → 肆 環境敏感地區 →
伍 通行條件 → 陸 隔離綠帶（或緩衝綠帶）方案 → 柒 綜合說明**

理由：綠帶是**方案配置**，要放在各項現況與法規檢核都講完之後；先講方案再回頭講現況，
讀者無從判斷那個方案合不合理。**基地區位是第一章，且第 2 頁必有區位圖**（規則15）。

⚠ 2026-09-09 麻豆客子寮段案實錯：把「隔離綠帶」排到「通行條件」之前、又沒有獨立的
基地區位頁，被使用者當場退回（「之前應該有固定過…請不要擅自修改」）。成因是下方 v1 表
把「基地區位」與「基地現況」擠在同一頁、該頁圖掛正射套疊，**與規則15「第2頁放區位圖」
自相矛盾**，照表做就會漏掉區位圖。**以本節順序為準**，下表僅供各頁內容與資料來源參考。

## 依基地面積決定內容深淺（★2026-07-29 使用者定案，四條通則）

**① 臨路圖一律回到基地尺度、與其他主題同比例尺（★2026-07-29 修正，優先於面積分流）。**
`make_maps ... --themes=臨路判定 --road-margin=0`。
周邊道路與聚落脈絡交給**獨立的區位圖**（見規則⑮）承擔，臨路圖只負責「路面距基地
幾公尺、路寬幾公尺」——那才是要判斷的事。外擴 700m（官田模式）僅在**沒做區位圖
且基地 ≥2 公頃**時才考慮；小基地外擴後基地縮成一個點，全部看不到。

**② 基地 < 1 公頃 → 不做排水／出流管制分析。**
法源＝出流管制辦法 §2-1 第 2 項（未達 1 公頃且已辦雨水流出抑制或貯滯留措施者得免提
計畫書）。第9頁總表仍保留「排水」一列載明免辦依據並給 ○，**但不要為它做一頁簡報、
也不要在其他頁鋪陳排水論述**。⚠️ 只是「不分析」，不是「當該法規不存在」——
達 0.2 公頃仍屬觸發，總表要寫出免辦的路徑。

**③ 環境敏感地圖面必須是「實際套疊的敏感圖層」。**
❌ 曾犯的錯：放國土利用調查圖充數（答非所問，看不出基地與敏感範圍的關係）。
✅ 用 `大量圖資轉換工具/scripts/make_env_map.py`：讀 `環境敏感套疊.csv` 挑出套疊面積>0
的圖層 → 解析到本機 `環境敏感相關/` 的 shp → 用同一套 maxmap 版面出圖，
並產 `環境敏感套疊_逐類面積.csv`（逐分級面積，簡報表格直接引用）。
**53 項全無套疊 → 整頁不做**，改在第9頁總表寫「經查詢均無涉環境敏感地」。

**④ 路寬認定以國土利用調查的道路判斷成果為主。**
即 `road_access.py` 的 `鄰接路寬中位數_m`（沿基地邊界法向量測道路面）。
不要拿官方道路中心線距離去推算路寬——那是「最近距離」不是「垂直路寬」，會系統性低估。
兩者衝突時以國土利用調查為準；官方中心線僅供交叉參考。

## 第9頁 法令檢核總表（★2026-07-26 使用者定案，取代舊寫法）

**圖例一律寫**：`○:具可行性　△:需經後續作業／審議認定　╳:不具可行性`
（**不再用「△ 有條件辦理」**。△ 的意思是「需作業後才知道可不可行」，例如涉及坡度、出流管制、
環評、海岸利用管理說明書等尚待審查者。）

- **記號正規化**：△＝Δ＝▲（統一輸出 △）；╳＝×＝X（統一輸出 ╳）；
  多宗地／多坵塊並列時，該法規不適用某宗地者填「**-**」（表非此法規之項目）。
- **欄位**：`評估事項｜相關法規｜法規要求｜基地情形｜判定` **五欄**
  （★2026-08-07 依兩案人工修正版改定：法規與條號併為一欄、原「翻轉條件／須辦事項」
  欄刪除並併入「基地情形」，詳見下方「法規評估表的定案寫法」節）。
  基地情形與判定**可依坵塊／宗基地展開為 N 欄**（與制式檢核表「北坵塊／南坵塊」、
  產線 persite 分組同構）。
- ~~**「執行疑義」列**~~ **已廢除**（★2026-08-07）：整案結論改放**表格外、頁面底部的
  獨立文字方塊**。原因見下方定案寫法節（長文字塞進表格列會整列消失）。
- **同一案若有多條可行辦理路線（開發許可／變更編定／容許使用／專案計畫），各出一張表分別判定**，
  不要只做一張。
- **臨路判定校準**：寬度不足 8 公尺**不必然是 △**——寫出可援引之但書／替代方案且能出具證明 → **○**；
  只陳述寬度不足 → **△**；完全不臨路且無替代通行方案 → **╳**。
- 法規、條號、判定門檻**一律取自法令檢核規則庫**（★2026-11-17 起由三辦公室共用 repo
  `Ykupic_ontology` 維護，同步到衍古知識庫
  `衍古\03_案件經驗知識層\70_法規索引\法令檢核規則庫\法令檢核規則庫.xlsx`／`.csv`；
  舊 `法令檢核規則庫_v9草稿.xlsx` 已封存，勿再引用；母體為衍古 71 層核心法規全文）。
  **不得憑印象寫條號**；規則庫標★待提供者（現有 4 筆）不可交付。

**第5頁的權威來源（2026-07-26 起）**:若案件目錄有 `國土功能分區.csv`（`nluz-landzone-query` 產出），
第5頁的分區認定**以該 CSV 的逐筆結果為準**（nluz 報部版），不要只憑圖面判讀。作法:
按 `國土功能分區` 欄 groupby 計數，面積用 gpkg 基地層幾何面積加總（**CSV 沒有面積欄，勿從 CSV 估面積**）。
`查詢狀態=查無` 的筆數要在頁面標註（通常是都市計畫區或清冊未登載，屬正常）。
CSV 的 `原使用分區`/`原使用地` 與②join 的 `使分`/`使類` 應一致，**不一致要在簡報標註**
（可能是清冊版本差異，不可自行選一邊當真）。仍須保留「草案示意、以直轄市/縣市政府認定內容為準」的免責。

各宗基地用地組成的算法:gpkg 基地層以正規化地號 join `sitemap.csv` → 依(案場×使類)
加總幾何面積、算站內比例(官田:S001 農牧88.2%+林業11.8%,S002–S004 全農牧)。

46. **不做頁間交叉引用**（「（詳陸章）」一律刪）。讀者不需要被指路，該頁講不完的
    事就是不該放那頁。

## ★ 寫作規則(2026-07-29 使用者逐頁改稿後定案,共 14 條)

使用者兩度手改西港案簡報,以下是從改動反推出的規則。**產稿時逐條自檢**。

### 結構:能收進總表的頁面就不要單獨做
1. **一頁必須提供總表以外的東西**(圖面、分級數據、多方案比較);否則併入第9頁總表。
   實例:「土地條件檢核」頁(面積門檻＋坡度)被整頁刪除——兩項在總表已有專列。
2. **總表不設「條號」欄**。條號寫在敘述裡或不寫,不佔一欄。
3. **基地<1公頃 → 總表連「排水」列都不列**(不是列一行寫免辦依據)。
4. **總表字級 11pt、列高交給自動增高**(設 0.28 當最小值即可)。不要為了固定列高壓縮文字。

### 寫作:只留結論
5. **不用文字複述表格**。表格已逐級列出的分級/面積/佔比,條列不再重述一次。
6. **方法論與技術細節不進簡報**。刪掉的實例:「以段代碼＋地號向內政部系統逐筆查詢」、
   「原使用分區欄空白為正常」、「沿基地邊界法向量測(16個取樣點)」、「中位數14.4公尺
   (13.84～14.4)」。→ 怎麼查的、幾個取樣點、為何空白,一律不寫;只留結論值。
7. **同一件事不要用三種形式講**。一頁的骨架＝**法規要求一句＋現況結論一句＋因應手段一句**;
   不要再配一張「要求/現況/認定」表。
8. **表格只在承載多列數據時才放**。單列表、只有 100% 的佔比欄 → 刪。
9. **環境敏感地用「涉及」不用「套疊」**(「僅涉及淹水潛勢」「全數無涉及」)。

### 內容實質
10. **法規清單要完整**。曾整條漏掉「**農業主管機關同意農業用地變更使用審查作業要點**」
    ——都市計畫農業區/保護區農業用地作非農業使用,須製作**農業用地變更使用說明書**
    並經農業局審查同意。凡「農業用地變更作非農業使用」的案子都要這一列。
11. **寫因應手段前必須先查清土地的權屬與管理機關**。手段完全取決於此:
    私有地→取得土地或通行權;**國有水利地→向管理機關申請搭設版橋(買不到)**。
    ⚠️ **本機 `周邊地籍` gpkg 只有 使分/使類 兩欄,沒有公私別/所有權人/管理者**——
    不可據以推論權屬(曾因此把國有水利地誤判為私地)。
    **查法(單筆最快,不必匯出Excel)**:TCDGIS 多重地籍選取加入該地號後直接讀清單列:
    `$('#tabCadalayer_SKINDA3').dataTable().fnGetNodes()[0].cells` →
    `[_,縣市,鄉鎮,地段,地號,公私別,所有權人,管理者,使用分區,使用地類別,公告現值,公告地價,標示面積,向量面積]`。
    實例:西港 227 → 公/國有(中央機關)/**農業部農田水利署** → 手段改為申請版橋。
12. **建議收斂成單一具體做法**,不要把選項丟回給使用者。
    實例:面積超標由「循但書(一)主張 或 剔除1筆」兩案並列 → 改為「**建議採土地分割**」。

### 區位與宗基地（★2026-07-29 新增）

### 判準校準與省略規則（★2026-07-29 第三、四輪使用者手改後定案）
21. **既成且確定的限制 → ○，不是 △。** ○ 是「具可行性（惟有此限制）」；△ 只留給
    **真正待審議或待後續作業**者。實例：全區位於地下水管制區第二級、日後不得鑿井引水
    ——這是確定事實與確定限制，判 **○**（原判 △ 是錯的）。
22. **兩案場情形相同 → S002 欄留空**，不寫「同左」（留空即表示同前欄，畫面乾淨）。
    **非逐案場的項目**（如營運管制）S001/S002 欄填「**--**」。
23. **給明確建議，不把選項丟回使用者。** 「建議剔除」「建議以S002為申請主體」，
    而不是「可循A或B」。建議要附驗算（剔除後面積是否仍過門檻）。
24. **純法規常數頁刪掉。** 只有法規值、沒有基地實況比對的頁面（如「使用強度與設施」
    只列建蔽率/容積率/圍牆規格）不成一頁，併入總表。
25. **不成立的法規義務整列刪除，不要留「－」佔位。**
    ★**非山坡地即不辦水土保持**（水保法§12 之對象為山坡地或森林區內土地）——
    平地案件的「水土保持」列直接刪，即使目的事業法規的申請文件清單有列水保計畫。
26. **淹水潛勢僅涉及 0-0.3 公尺級者，視為未涉及**——不列表、不繪圖、不敘述。
    0-0.3m 是積水而非致災性淹水；TCDGIS 該圖層本來也只計 ≥0.3m（故平台回報 0）。
27. **國有地取得有兩道獨立的法律門檻，都要查**（2026-07-29 實例：1070 地號兩關全卡）：
    - **位於都市計畫範圍內 → 不得同意提供申請開發**
      （國有非公用土地提供申請開發案件處理要點§3①(三)，112.09.15 台財產管字第11240009760號令）
    - **非公用空地面積在 1,650 平方公尺以上 → 不得標售**（國有財產法§53，107.11.21）
    兩者皆不可行時，結論是「建議剔除該筆」，並**驗算剔除後面積是否仍過各門檻**
    （面積下限、日進出場量級距、環評門檻）與**幾何是否仍連通、有無內孔**。

### 交付品質（★2026-07-29 安南案新增）
28. **交付字串不得含 markdown 標記。** PowerPoint／Word 不解析 `**`、`##`、`` ` ``——
    會字面印在交付文件上（安南案實錯：總表印出「★ ** 經政府核定… ** 」）。
    要強調就用 run 的 `font.bold = True`，或靠語序（內文不用 ★，見規則41）。
29. **長法規名第一次出現就定簡稱**，後續一律用簡稱。

    （以下簡稱自治條例）」，之後總表「相關法規」欄即寫「自治條例§18①2」。
30. **╳ 不是句點，要寫出「翻轉條件」並註明是否在申請人控制範圍內。**
    安南案兩個翻轉條件（①改由政府機關興辦 ②生產區公告廢止或縮小範圍）**都不是申請人
    可自行達成**——這句話對業主的決策價值遠高於單一個 ╳。同理 ○ 也要寫出前提。
31. **「十戶以上之村莊或聚落」是先認定聚落、再量距離，不是數環域內幾戶。**
    正解三步：門牌點聚類 → 該群門牌數達十 → 量基地到**該聚落**最短距離。工具＝
    `大量圖資轉換工具/scripts/settlement_check.py`（門牌坐標開放資料，check_zones 的
    `settlement` 項目會自動呼叫）。安南案 200 公尺內只有 5~6 個門牌、最近單一門牌僅
    2.7 公尺，兩種簡化寫法一個理由錯、一個結論反；正解是最近之十戶以上聚落（城西里）
    S001 328.0 公尺／S002 281.9 公尺 → 未觸及。
    **寫法**：①寫「門牌數」不寫「戶數」②註明群聚門檻與敏感度（30/50/100 公尺三者一致
    才寫單一結論）③附口徑「門牌坐標係戶政人工點位、僅供參考，法定認定以戶政事務所
    ／區公所為準」④臨界值（8~12）不得逕下結論，寫明須現地或戶政查證。

## 工具鏈與本機注意(踩過的坑)

- pptxgenjs 全域安裝後 node 找不到 → `export NODE_PATH=$(npm root -g)` 再跑。
- pptx skill 的 `validate.py` 在 Windows 要 `PYTHONUTF8=1`,否則 cp950 讀 SKILL/中文檔炸。
- pptx skill 的 `soffice.py` 包裝在 Windows 失敗(AF_UNIX)→ 直接呼叫
  `"C:\Program Files\LibreOffice\program\soffice.exe" --headless --convert-to pdf`。
- `pdftoppm` 沒裝 → 用 PyMuPDF(`fitz`)把 PDF 逐頁存 jpg。
- 地圖 PNG 是 RGBA,存 jpg 前先 `.convert('RGB')`。
- QA 必做:validate 全過 + 每頁渲染目視(溢出/重疊/佔位殘留)。
- **★逐頁核對「圖＝該頁主題」**(2026-08-05 後壁南海段社福實踩):`build_deck.py` 每個
  `D.pic(...)` 接的圖,必須是**該頁主題的實際成果圖**,不可用區位圖(LOC)或別頁的圖充數。
  兩個常犯處:①**主題圖根本沒產**就先寫接圖那行(緩衝綠帶頁忘了先跑
  `make_extra_maps --theme 緩衝綠帶`,拿 LOC 頂替);②圖檔變數接錯(定義了 GRB 卻寫成 LOC)。
  → 出簡報前先確認**每個主題頁的成果圖都已產出**(make_maps/make_extra_maps/make_env_map/
  make_locality_map),再逐頁目視「標題講的主題」與「圖的內容」相符。這與規則③「環敏頁要放
  實際套疊圖層」是同一類錯(接錯圖/答非所問),**不限環敏頁,任何主題頁都要核**。
- **★★做簡報前:本機圖資 vs 平台/NGIS 不一致要先列清單給使用者確認,不得自行拍板或過度
  推論**(2026-08-10 使用者定案,潮州水庫案實錯):①分類/屬性不同(一級 vs 二級、面積、供水別、
  管理機關…)→預設以平台/NGIS 為主,但**仍先列「不一致清單」交使用者逐一確認,確認後才寫進
  簡報**;②交付文字**每個數字/屬性都要能指出來源**,分清「圖資查得」與「推論」——欄位空白
  或靠資料夾名/常識反推的**不可寫成事實**,要列為待查證。實錯:潮州案把水庫「供工業用水/
  南區水資源局」從資料夾名與常識反推、直接寫進簡報,未先列給使用者確認(TYPE 實為供家用、
  UNIT 欄空白)。**只要靠推論,先問、別寫死。**
