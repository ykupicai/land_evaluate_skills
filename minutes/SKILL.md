# 會議紀錄草稿產製(DRAFT mode)

用法:`/minutes <逐字稿路徑>`(可加補充指示,如指定範本或輸出位置)。

## 鐵律(違反任一條即整批重來)

1. **來源唯讀**:絕不將來源檔 ingest 進任何資料庫;絕不搬移、改名、刪除或 git commit 任何檔案。
2. **雙產出**:必須同時產出 `<原檔名>_紀錄草稿.docx` 與 `<原檔名>_result.json`,寫到來源檔同層
   (使用者另有指定則從其指定);絕不覆蓋既有檔,同名時加流水號。
3. **法條必查證**:紀錄中每一條法規/函釋引用,定稿前必須逐條 web 查證條號與現行內容;
   查證不符就修正,並把「原引用→修正後→查證來源」記入 result.json。歷史上曾出過引用錯誤,
   只靠逐字稿內容照抄不算查證。
4. **繁體中文**:全部產出與回應一律繁體中文(台灣用語),禁止日文/簡體——即使逐字稿夾雜其他語言。

## 產製流程

1. 讀逐字稿(只讀,不動檔),辨識發言人並統一稱謂;無法確定者標「(待確認)」。
2. **分段生成、逐段落地**:長逐字稿依議程段落分段產出,每完成一段就寫入磁碟
   (先寫 markdown 中繼檔再組 docx),避免單次長輸出撞 output token 上限前功盡棄。
   中斷後從中繼檔續作,不重生成已完成段落。
3. docx 格式:案件資料夾有既有紀錄範本就照範本;沒有則用標準結構
   (會議名稱/時間/地點/出席/主席/報告事項/討論事項/決議/臨時動議)。
   docx 產製用 anthropic-skills:docx skill,metadata 一律 UTF-8。
4. 每份 docx 首頁頁首標「草稿 DRAFT——未經確認」。

## result.json 必含欄位

```json
{
  "source": "來源檔路徑",
  "output_docx": "產出檔路徑",
  "speakers": ["發言人清單(含待確認者)"],
  "citations": [{"original": "…", "verified": "…", "corrected": true, "source_url": "…"}],
  "pending": ["待確認事項(人名、數字、聽不清楚段落)"],
  "generated_at": "ISO 時間"
}
```

## 常見失敗(皆為實際發生過)

| 症狀 | 對策 |
|---|---|
| 法條引用照逐字稿抄、條號錯誤 | 鐵律 3:逐條 web 查證,不查證不得交付 |
| 回應/產出飄成日文 | 鐵律 4:任何階段發現非繁中立即改正重出該段 |
| 長逐字稿生成到一半撞 token 上限 | 流程 2:分段落地,絕不單次生成全文 |
